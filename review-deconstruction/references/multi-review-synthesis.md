# 多篇综述拆解的聚合方法（2+ 篇拆解表存在时使用）

目的：把若干篇单独的拆解表交叉成一份**写作决策清单**，直接指导用户自己的综述。

## 步骤

1. **建交叉表**：行 = 8 个拆解维度；列 = 各篇综述。每格一句话概括该篇在该维度上的做法。
2. **标共识**：
   - 所有范本都做的 → 「采纳」，默认写进自己的综述，除非自己的定位有明确理由不这么做
   - 所有范本都踩的坑 → 「规避」，写进自己的自查清单
3. **标分歧**：范本之间做法不同的维度（如主线选时间还是选任务、taxonomy 放前还是放后）→ 用户必须**主动选择并写一句理由**，理由要绑定自己综述的目标（如"我的目标是找缺口，所以主线选任务链"）。
4. **合并语料库**：把各篇采集的串联句式去重合并，按功能分类（界定句/转折句/对比句/收束句），形成用户自己的句式库。
5. **产出物**：一张「写作决策表」（Markdown 表，含采纳/规避/待定三列）+ 分类句式库。存为用户综述项目的 `notes/写作决策清单.md`。

## 判定质量标准

- 每个"采纳"项都有 ≥2 篇范本支撑；每个"规避"项都有 ≥2 篇范本支撑
- 每个"待定"项都有明确的选择和一句理由（不允许"看情况"）
- 决策表里的每一项都能追溯到具体拆解表的某一格（保留编号引用）

## 常见失败模式

- 只聚合不决策：列了差异但不选边 → 等于没做
- 过度聚合：把内容性发现（某领域的事实）混入写作决策 → 内容发现属于各拆解表的"副产品"区，不进入本表
- 忽视定位差异：用户综述与范本的目标不同时机械照抄共识 → 共识只是默认项，定位冲突时以定位为准并记录理由
